Setup — deploy the Apps Script (owner of the sheets does this once)

  1. Open the trylist Google Sheet → menu Extensions ▸ Apps Script. A script editor opens with an empty Code.gs.
  2. Delete its contents and paste the whole of apps_script.gs (in this folder). The two sheet IDs and the two passwords are already filled in at the top — change them there if you ever rotate a password.
  3. Click Run ▸ testRead once. Google asks you to authorise the script to access your spreadsheets — accept (it runs as you; nobody else ever logs in). The log should show both sheets' first rows.
  4. Deploy ▸ New deployment → gear icon → type Web app. Description anything. Execute as: Me. Who has access: Anyone. Click Deploy.
  5. Copy the Web app URL (it ends in /exec).
  6. Open Japan_Trip_Guide_V72.html in a text editor, find near the top:
    var SHARED_API_URL = "";
    and paste the URL between the quotes. Save. Send this HTML to the group (or put it in the shared folder).
  7. Open the guide: the To-try (Shared) and Tabung panels now say live from the Google Sheet. Tick something — the row in the Sheet changes within a second.
If you later change the script (e.g. a password), use Deploy ▸ Manage deployments ▸ ✎ ▸ Version: New version ▸ Deploy. The URL stays the same, so the HTML does not need to change.
Sharing the sheets: “anyone with the link can view” is enough for the read-only fallback and for the script (the script writes as its owner). Give edit rights only to people who should be able to change rows in the Sheets app directly.

How a write works (for the curious)

The guide sends the whole tab (all rows) plus the revision it last saw. The script locks, checks the revision still matches, rewrites the tab, bumps Meta → revision and returns the fresh copy. If two people edit within the same second, the second one gets “someone else changed the list first — reloaded, please redo”, so nothing is silently overwritten. Typing in a field is coalesced into one write about a second after you stop.

1. The one thing to understand first

先搞懂这一点
A web page can read a file next to it, but it can never write into your folder. That is why the file mode below is a download-and-replace loop, and why the live mode above needs the small Apps Script as the writer. So, in file mode:
① ReadWhen the guide opens it looks for data/… and loads whatever is there.
② EditIn the guide (after the password) or straight in Excel / a text editor.
③ DownloadGuide edits produce a fresh trylist.xlsx / tabung.xlsx with revision +1.
④ Put backDrop the downloaded file into data/, replacing the old one. Everyone sees it next time.

Automatic vs. manual loading

  • Hosted / opened over a link (http or https) — OneDrive/SharePoint/Google Drive web preview of the folder, a company intranet folder, GitHub Pages, a NAS, or a laptop running python -m http.server in the folder: the three files load automatically every time the guide opens. Nothing to do.
  • Opened as a plain file (double-click → file:///…, or sent through WhatsApp): the browser is not allowed to read the sibling files. Each person taps 📂 Load data files once (the button sits at the top of the guide, in the To-try list and in the Tabung), selects the two/three files from data/ in one go, and the copy is cached on that phone until a newer revision is loaded. Repeat when someone announces a new revision.
Recommended for the trip: keep the whole folder (HTML + data/) in one shared cloud folder everyone has offline access to. On the phone, open the HTML from the cloud app; when a new Excel is put back, everyone re-taps “Load data files” (or the files load by themselves if the folder is served over http).

2. The status panel

状态栏怎么看

Each shared section shows a small dashed panel:

  • ● green — loaded, clean. rev 3 · from the shared folder · 9 Oct, 21:15 tells you which revision this phone is looking at and where it came from (shared folder = automatic, loaded on this device = via the button).
  • ● orange + ⚠ 2 edit(s) not yet in the shared file — you changed something here; nobody else can see it until you press ⬇ Download updated Excel and put the file back.
  • ⬇ downloaded — waiting to be put back in data/ — you exported; the folder still has the old file.
  • grey — shared file not loaded — showing the built-in copy (To-try) or this device's own ledger (Tabung). Tap 📂 Load data files.
  • 🔒 Enter password to edit / 🔓 Unlocked · lock again — the password is asked once and remembered on that device. Lock again before handing your phone to someone who shouldn't edit.
Revision rule. Every export bumps Meta → revision by 1. A phone that already holds revision 5 ignores a copy with revision 4, so two people's exports can't silently roll each other back. If two people edited at the same time, the second one to put back a file must first load the other's file, redo their edits, then export — the guide will ask “a newer file was found… replace your N edits?” to make this obvious.

5. The 8-day tour — data/tour_8d.json

8天行程 JSON

When this file loads, the guide throws away the Day 1–8 rows baked into the HTML and redraws them from the file. Nothing else (coupons, shopping list, route calculator, Shibuya lane picker…) is touched. To change the itinerary you edit only this file — never the HTML.

Shape

{
 "_readme": "…",
 "version": 1,                       ← bump by 1 every time you save
 "updated": "2026-09-17",
 "days": [
  {
   "day": 6,
   "title":   {"en": "Tochigi → Ibaraki → Tokyo", "zh": "栃木 → 茨城 → 东京"},
   "meta":    {"en": "Fri 9 Oct · stay: Shinjuku Granbell Hotel (Kabukicho)", "zh": "10月9日 周五 · 住：新宿格兰贝尔酒店（歌舞伎町）"},
   "weather": {"en": "<b>28° / 19°</b><br>cloudy", "zh": "<b>28° / 19°</b><br>多云"},
   "blocks": [
     [ …rows before the Shibuya lane picker… ],
     [ …rows after it… ]
   ]
  }
 ]
}

A day has one or more blocks (Day 6 has two because the Shibuya lane picker sits between them; every other day has one). A block is a list of rows, top to bottom.

A row

{"time": "21:50",
 "class": "add",
 "en": "<span class=\"badge add\">ADD-ON</span><b>Daikoku Drug Kabukicho 2-chome</b> …",
 "zh": "<span class=\"badge add\">加点</span><b>大国药妆 歌舞伎町2丁目店</b> …"}
fieldmeaning
timeText shown in the left column: "7:30", "21:50". Can be blank.
class"" grey tour row · "add" gold ADD-ON · "kon" green konbini run · "kon vital" 🟠 stock-up konbini run.
en / zhThe row text in English and Chinese. Plain text is fine; HTML is allowed (the existing rows use <b>, <span class="dist">, <ul class="pts">…). Copy an existing row of the same kind and change the words.
attrsOptional. Day 6 Shibuya rows carry {"data-lane": "east"} (east / west / sw / ne) so the lane picker can filter them.
rawA few complex blocks (e.g. the Day 7 ALT PLAN) are stored verbatim as one HTML string. Leave those alone unless you are comfortable with HTML.

How to edit safely

  1. Open data/tour_8d.json in VS Code / Notepad++ (anything that shows JSON errors). Keep the file UTF-8.
  2. Find the day ("day": 6) and the block; insert, move or delete a row object. Rows are separated by commas — the last one in a block has no trailing comma.
  3. Inside en/zh, write quotes as \". Newlines are not needed.
  4. Bump "version" by 1, save, and paste the file into jsonlint.com once — a single missing comma makes the guide fall back to the built-in rows (it says so in the browser console, nothing breaks).
  5. Put the file back in data/. Hosted folders pick it up on the next open; plain-file users re-tap 📂 Load data files.
The checklist in Japan_Trip_Guide_V71.md (“How to add a new location”) still applies — route-calculator coordinates, coupon chips and shopping-list where fields live in the HTML and are not part of this file.
